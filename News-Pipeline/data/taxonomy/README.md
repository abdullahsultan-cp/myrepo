# data/taxonomy

Output of `pipeline/taxonomy/`. Everything here is regenerated by
`python pipeline/taxonomy/run_taxonomy.py`.

Spec: [`docs/MIGRATION_DECISIONS.md`](../../docs/MIGRATION_DECISIONS.md).

---

## `seed/` — hand these to the backend

| File | Contents |
|---|---|
| **`folders.json`** | 346 folders, no stories. Flat list ordered **parent before child**, plus the same nested as `tree`. This is the one for creating the structure. |
| `folders_tree.txt` | the same as an ASCII tree |
| `folders.csv` | the same flat list as a spreadsheet |
| `regions_entities_departments.json` | the same tree in the **front end's** nested shape — `region → entities → departments`, each with `name`, `slug`, `short_name`, `has_news`. From `export_dev_tree.py`. |
| `storyblok_seed.json` | folders **and** all 3606 stories, with destination, share targets and provenance |

Every folder carries `entity_short`, `department_short` and a `short_name` that
mirrors its own level. Entity shorts are derived from AKU approver-group names;
department shorts are hand-authored in `config/department_abbrev.csv`.

Check a hand-maintained copy before anyone creates folders from it:

```bash
python pipeline/taxonomy/validate_dev_tree.py their.json --csv diff.csv
```

Both JSON files are validated on generation and the generator exits non-zero
rather than writing a broken file: every folder parent resolves and precedes its
child, every story's folder exists, every share target exists, no duplicate
slugs.

| File | Contents |

## `intermediate/` — one file per stage

Kept so any derived field can be traced to the rule that produced it. Regenerable
and safe to delete.

`news_structure.csv` (region + `region_source`) · `entity_abbrev.csv` ·
`recovered_entities.csv` + `_still_no_entity.csv` + `_recovery_summary.csv` ·
`_items_departments.csv` + `_departments.csv` + `_no_department.csv` +
`taxonomy_derived.csv` · `connections.csv` + `clean_sheet.csv` · plus the
`taxonomy*.csv` / `department_tree.*` / `_tree*` review sheets.

## `lookups/` — what the export actually references

`lk_cities.csv` · `lk_entities.csv` · `lk_tags.csv` · `lk_approvers.csv` ·
`region_map.csv` · `_drift.txt`

`_drift.txt` is worth reading once: 228 tag labels, most carrying 2–4 different
`TermGuid`s for the same label. **Dedupe tags by label, never by GUID.**
